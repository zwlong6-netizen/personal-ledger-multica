# 个人记账本全流程测试用例矩阵与自动化测试方案规格书

---

## 1. 测试范围与质量目标

根据 **TASK-1 MVP 产品需求规格说明书 (PRD)** 与 **TASK-3 技术架构与核心 API 接口定义规格书**，制定本测试工程方案。

### 1.1 核心质量目标
1. **金融级计算准确度 (Zero Precision Loss)**：严格确保无 IEEE 754 浮点累加偏差，所有底层计算以“分”（64位整型 BigInt）为基准，满足 0.01 最小单位与上限金额极限运算。
2. **时区边界无错位 (Strict Timezone Alignment)**：严格对齐客户端自然月边界（UTC+8等），月末 23:59:59.999 与次月 00:00:00.000 毫秒级划分无跨月错位，支持闰年与平年计算。
3. **数据关联完整性 (Referential Integrity)**：预置分类只读保护，自定义分类关联交易删除严格拦截（409 Conflict），杜绝脏数据孤儿账单。
4. **报表聚合严格一致 (Mathematical Consistency)**：月度总收支、分类聚合明细求和、日趋势累加求和三者之间满足 100% 数学一致性比对。

## 3. 自动化测试执行方案与规范

### 3.1 自动化测试架构设计
测试工程采用分层测试模型（Testing Pyramid）：
- **单元与规范测试（Unit Tests）**：针对 `Currency` 金额计算、`Timezone` 跨月时间戳换算、`Category` 业务完整性规则进行纯函数级单测，运行速度达到毫秒级。
- **集成与契约测试（Integration / API Contract Tests）**：通过 HTTP Client 针对 `/api/v1/*` 端点进行 REST API 契约与 Schema 返回校验。
- **端到端冒烟测试（E2E Smoke Tests）**：模拟真实用户路径，保障主流程稳定交付。

### 3.2 技术选型与工具链
- **测试执行器**：**Node.js Native Test Runner (`node:test`)** 与 **Vitest / Jest** 语法 100% 兼容。
- **断言库**：**`node:assert/strict`** 深度相等与严格类型断言。
- **代码规范与执行命令**：
  ```bash
  # 运行全部测试用例
  node --test tests/unit/*.test.mjs

  # 运行特定模块用例
  node --test tests/unit/currency.test.mjs
  node --test tests/unit/timezone.test.mjs
  node --test tests/unit/category.test.mjs
  node --test tests/unit/aggregation.test.mjs
  node --test tests/unit/smoke.test.mjs
  ```

## 4. 冒烟与验收标准 (Acceptance Criteria)

### 4.1 冒烟测试准入标准 (Smoke Gate)
- 所有标注为 **P0 (冒烟)** 的测试用例（包括 `SMOKE-001`、`TC-CURR-001`、`TC-CURR-006`、`TC-TIME-001`、`TC-CAT-001`、`TC-AGG-001`）执行通过率必须达到 **100%**。
- 自动化测试执行时间不超过 **5 秒**，无偶发性（Flaky）失败。

### 4.2 交付验收准则 (Release Criteria)
1. **测试矩阵 100% 覆盖**：矩阵中所列全部 23 项核心及边界用例均已实现自动化脚本并绿灯通过。
2. **零浮点偏差**：在 10,000 次微小金额连续累加与大额边界下，金额误差为 0。
3. **时区一致性**：在 `Asia/Shanghai` 时区下，月末 23:59:59.999 与次月 00:00:00.000 划分准确率 100%。
4. **数据安全防护**：预置分类与带账单分类物理删除拦截率 100%。
5. **报表闭环自洽**：任何月份的统计看板总额与流水明细严格相等。
